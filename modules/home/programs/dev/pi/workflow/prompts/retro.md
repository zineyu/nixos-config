在切片收尾（`/close-out`）之后运行，也可以单独运行。本流程禁止修改实现代码。

## 沉淀知识

回顾本次工作：新确立的约定、踩过的坑、评审中暴露的模式问题。凡是下一个会话需要知道的，写入对应位置：

1. 仓库规范与流程：`AGENTS.md` 及各层级说明文件。
2. 领域术语：仓库的术语表（如 `docs/glossary.md`，不存在时创建）。
3. 设计取舍：`docs/adr/` 的新 ADR（已有 ADR 的正文保持不动，新的决策写入新文件）。

只写沉淀，不写过程记录；删除已经失效的内容，禁止补丁式堆积。

## 复盘环境

评估 agent 环境本身——导航、自动检查、编码规范、工具——是否有值得改进之处，按严重度排序报告给用户，由用户决定是否采纳。改进项按以下类别寻找：

- **导航**：agent 找到正确文件的难度如何？文件之间是否有隐藏依赖？加一个导航指针是否会更容易？适用于会话花很长时间才找到某条信息的场合。
- **自动检查**：是否存在能抓住 agent 所犯错误的自动检查（lint、类型、测试、文件系统 linter）？先读仓库自己的检查命令（构建工具的 `lint`/`check` 脚本、CI workflow）：已经存在但没有接线或者静默损坏的检查本身就是发现。完全没有护栏（无 pre-commit 钩子、无 CI 任务运行 lint/typecheck/test）的仓库本身也是发现：未接线的检查是持续错失的机会，不是中性默认。适用于 agent 犯了自动检查可以抓住的错误、或者仓库完全没有护栏的场合。
- **编码规范**：是否该给 reviewer agent 一条新规则？是否该移除或者澄清一条既有规则？先分类违规：机械违规（固定的语法模式、禁用的 API、import 形态、文件位置规则）一律落成确定性检查——仓库自己的 linter 加自定义规则、新的 pre-commit 钩子、或者新的 CI 任务，按仓库语言与既有护栏选最便宜的；默认造检查而不是写规则。`CODING_STANDARDS.md` 只留给真正的判断题（跨文件一致性、「与周围风格一致」、任何护栏无法替代的内容）。适用于 reviewer agent 没有抓住某个错误的场合。
- **全局 AGENTS.md**：是否有转向指令应该移到编码规范（或者自动检查）？适用于仓库内或者用户全局的 AGENTS.md 特别大的场合。
- **工具经济性**：agent 是否有可以精简的昂贵工具调用？是否有特别耗费 token 的自定义工具（CLI、MCP）？适用于 agent 发出昂贵工具调用的场合。
- **空转指令**：转向文件里是否存在不改变 agent 行为的指令？适用于转向文件大而臃肿的场合。
- **信息可达性**：是否有扩大 agent 信息访问的机会？把开发服务器日志落盘、给第三方服务只读访问。适用于关键信息 agent 拿不到的场合。

记住实施与评审的分工：实施 agent 上下文压力最大，负责探索、写代码、调试；reviewer agent 上下文压力最小，拿到 diff、不需要探索。因此编码规范由 reviewer agent 负责执行，不由实施 agent 负责。

报告改进项时遵循 writing-for-agents skill 的写作规范。

## 报告

报告写入的文件清单、新增的 ADR 与术语、环境改进建议。
